# Presentation / UI — Specs

Design: [ui-design.md](ui-design.md)

## The page

- [x] **UI-SHELL-001**: When the page starts with no saved run, or one that fails to load, the UI shall show the start screen and draw a new seed from the browser's cryptographic random source, and when the player begins, start a new run from that seed and show it.
- [x] **UI-SHELL-002**: When the UI shows a run, it shall show the week screen in the week phase, the review screen in the review phase, the handover screen in the handover phase, and the ended screen once the run has ended.
- [x] **UI-SHELL-003**: When a command applies, the UI shall redraw the whole screen from the new run.
- [x] **UI-SHELL-004**: If a command returns an error, then the UI shall show the error next to the control that sent it and leave the rest of the screen as it was.
- [x] **UI-SHELL-005**: When the scene changes (after an answer, a wait, Continue, starting the week, closing the recap or ending the week), the UI shall move keyboard focus to the heading of the week screen's scene, or of the review or ended screen; after a habit change it shall keep focus on that habit's control.
- [x] **UI-SHELL-006**: When the start screen is shown, the UI shall show the disclaimer text the UI design sets.
- [x] **UI-SHELL-007**: When the start screen is shown, the UI shall show "Version " followed by the version the build stamped.
- [x] **UI-SHELL-009**: When the start screen is shown, the UI shall show the line "Every promotion is a new job.", the pitch the UI design sets, a **Start a new game** button that begins a run, and a **Load a saved game** button that opens the file picker for a save to import.
- [x] **UI-SAVE-009**: When a run screen is shown, the UI shall offer the import of UI-SAVE-007 as a **Load a saved game** button that opens the file picker, beside **Export save** and **Discard and start over**.
- [x] **UI-SAVE-010**: When another tab writes or removes the stored save, the UI shall stop saving and stop play in this tab, and show "This run was played on in another tab, so this tab stopped saving to keep from overwriting it." with a **Continue here** button that loads the stored save as UI-SAVE-001 does, or shows the start screen when there is none.

## Accessibility

- [x] **UI-A11Y-001**: The UI shall hold the game in the page's one main landmark, and give every screen one level-one heading; on the week screen, one for screen readers only that names the level and the turn, as "{Level}, {turn} {n}".
- [x] **UI-A11Y-002**: When the end-to-end tests show the start screen, a turn's opening scene, a moment and the recap, in light and dark mode, an automated WCAG 2.2 AA check with best practices shall find no violation.
- [x] **UI-SHELL-010**: When the start screen is shown, the UI shall show the career ladder as an ordered list from line manager to director and above, each rung with its level name, "You manage" followed by who the player manages, and "Each turn is" followed by the length of a turn, as the UI design's table sets them.
- [x] **UI-SHELL-013**: The UI shall start the game with the line manager and senior manager levels, in that order, so a promoted line manager is handed over to the senior manager.
- [x] **UI-SHELL-011**: When the start screen shows the career ladder, the UI shall mark a rung **Playable now** when the game was started with any of the level modules the UI design assigns to that rung, and **Coming later** otherwise.
- [x] **UI-SHELL-012**: When the start screen is shown, the UI shall show the copyright notice "© 2026 Twelve Chairs Software. All rights reserved."
- [x] **UI-SHELL-008**: The UI shall not show a run's seed on any screen.
- [x] **UI-TEXT-002**: When the UI shows situation text, it shall show each span wrapped in `*` or `_` as an emphasized element whose text is set as text, and show an unmatched marker as written.
- [x] **UI-TEXT-001**: The UI shall put every string from content, the simulation or the player on the page only as text nodes or as attributes set as text, and shall never parse HTML from a string.

## The week screen

- [x] **UI-WEEK-001**: When the week screen is shown, the UI shall show a header with the week the scene is about (while the recap is shown, the week it recaps), the weeks until the next review, the five days with the current moment's day marked and earlier days shown as past, the player's energy as a meter and a band word, their reputation as a band word, and each of the review period's goals with its progress.
- [x] **UI-WEEK-002**: When the week screen shows the current moment, the UI shall show its day and time in words (such as "Tuesday morning"), its title and text, a button per choice that sends an answer command for it, and a Let it wait button that sends the wait command.
- [x] **UI-WEEK-017**: When the week screen is shown, the UI shall show in the header where the player stands toward their own promotion: from the active level's last acknowledged review, in the review screen's words for it, and nothing once it has none to say; before the level's first review, "Promotion opens at your third review, then takes two reviews in a row rated exceeds or better."
- [x] **UI-WEEK-003**: When the week screen shows the current moment or a reaction, the UI shall show an End the week button beside the scene that sends the end-week command, and shall show no such button beside the Before Monday scene, the recap or the week-done scene.
- [x] **UI-WEEK-004**: When the week screen is shown after a week has ended, while no moment of the new week has been answered or let wait and the player has not closed the recap, the UI shall show the recap, set at the weekend, in place of the current moment: the level's part of the recap for what changed, then a disclosure titled "The whole week" holding each of last week's moments in order with its day, time, title and what happened (its reaction or aftermath line, that it was let wait, or that it passed), followed by the level's routine part, and a Start week button that closes the recap; before the first week ends it shall show no recap.
- [x] **UI-WEEK-015**: When the recap is shown on the week screen, the UI shall show its disclosure closed, unless the player has opened or closed a recap's disclosure since the page loaded, in which case it shall show it as the player last left it; it shall keep that choice only as page state, never in the run or the save.
- [x] **UI-WEEK-005**: When the week screen is shown in game week 0 before the player has started the week and while no moment of the week has been answered or let wait, the UI shall show a Before Monday scene with each habit, a line on what it does and a control to change it, the How to play section open, and a Start the week button that closes the scene.
- [x] **UI-WEEK-006**: When a choice for the current moment applies, the UI shall show that moment's reaction or aftermath line, or that the moment passed when it expired, with the change chips, a line naming each later moment of the week that the answer left expired, and a Continue button, in place of the next moment, until the player presses Continue.
- [x] **UI-WEEK-007**: When the week screen is shown with no open moment left and no reaction waiting, the UI shall show that the week is done, set at the weekend, with an End the week button.
- [x] **UI-WEEK-008**: When a choice for a moment applies, the UI shall show a change chip for each band in the level's view that differs from before the command (a person's motivation or stress, the player's energy or reputation, or a project's risk or tech debt) and for each person who left or joined the team, each naming who or what changed and marked good or bad for the player (lower stress, risk and tech debt are good; someone leaving is bad).
- [x] **UI-WEEK-010**: When a choice for a moment applies, the UI shall show a change chip, marked neither good nor bad, with the newest memory note of each person who gained one from the command and has no band chip from it.
- [x] **UI-WEEK-018**: When a choice for a moment applies, a level's moment or a situation at any career level, and the player's stress in the simulation is higher than before the command while the player's energy band is unchanged, the UI shall show a change chip "You: energy spent", marked bad.
- [x] **UI-WEEK-019**: When a choice for a moment applies, a level's moment or a situation at any career level, the UI shall show a change chip "{name}: a heavier week", marked bad, for each person the level's view shows whose stress in the simulation is higher than before the command and whose stress band is unchanged.
- [x] **UI-WEEK-011**: The UI shall show every week number counting from 1, game week *w* as week *w* + 1: the header's week, a heading or button about a week that has ended or is starting (the recap's heading, Start week, the review's heading, the ended screen), and the line manager's project deadlines.
- [x] **UI-WEEK-016**: When the active level's turn is a month or a quarter, the UI shall name the turn as a month or a quarter counting from 1 from the level's start week, in the header, the recap's heading ("How month *n* went"), its button ("Start month *n*"), the review's heading ("Month *n* review") and the weeks to the next review ("*n* months to your review"), and give a moment's place as its week of the month and day ("Week 2, Tuesday morning"), with the header's strip showing that week's five days.
- [x] **UI-WEEK-012**: When the week screen is shown while the level says the player is at the burnout threshold, the UI shall show their energy word as "at the edge" in place of the band word.
- [x] **UI-WEEK-013**: When the week screen is shown after the player has ended one or more consecutive weeks at the burnout threshold, the UI shall show under the energy a warning with that count and how many end the run ("You've ended 1 week at the edge. 4 in a row and you burn out.").
- [x] **UI-WEEK-014**: When the week screen is shown while the player's energy band is running on fumes and no week has ended at the burnout threshold, the UI shall show under the energy the warning "You're close to the edge. Take something off your plate."
- [x] **UI-WEEK-009**: The UI shall keep whether the player has read the latest reaction, started week 0 and closed the latest recap only as page state, never in the run or the save, so a reload never shows a reaction again.

## Help

- [x] **UI-HELP-001**: When the week screen is shown, the UI shall show a collapsible How to play section with the active level's help topics (for the line manager: How to play, Moments, Habits, Your people, Energy, Reviews; for the senior manager: How to play, Managers, What you're told, Calibration, Energy, Reviews), open by default in the level's first three turns and closed by default after, keeping the player's choice to open or close it across redraws.
- [x] **UI-HELP-002**: When the week screen is shown for the line manager, the UI shall show the help text's line under the team, projects and habits panels' headings.

## Line manager panels and scenes

- [x] **UI-LINE-001**: When the week screen is shown for the line manager, the UI shall show a card for each engineer with name, role, personality, tenure ("1 week here", otherwise "N weeks here"), performance level, motivation, stress and skill as band words, their want or that it is unknown, and their memory notes, newest first.
- [x] **UI-LINE-002**: When the week screen is shown for the line manager, the UI shall list each active project with name, progress against scope, deadline week, schedule status as on schedule, behind or overdue, and risk and tech debt as band words.
- [x] **UI-LINE-005**: When the week screen is shown for the line manager, the UI shall show each open vacancy with its interview count ("1 interview so far", otherwise "N interviews so far").
- [x] **UI-LINE-006**: When the week screen is shown for the line manager, the UI shall show a habits panel, folded by default after week 0 and keeping the player's choice to open or close it across redraws, with a control per habit that sends a plan command changing it at once, offering the team's engineers by name for a habit that names one.
- [x] **UI-LINE-012**: When the UI names the line manager's night pages settings, it shall name them by who is on call and whether they are on their own, as "Each engineer in turn, a week on their own" (a rotation), "Each engineer in turn, with the strongest of the others as backup" (a backup), "The most skilled engineer, on their own every week" (seniors) and "You, every night" (you); and its line on what the habit does shall say that whoever is on call handles the pages they can on their own, that a backup takes on with them the pages beyond them that the backup can handle, at a cost to the backup's sleep, and that a page beyond them comes to the player.
- [x] **UI-LINE-013**: When the recap is shown for the line manager and the level reports a watch line, the UI shall show it last in the recap's part for what changed, after "A quiet week." when that is shown, set apart from the lines above it under the label "Watch".
- [x] **UI-LINE-007**: When the current moment is the line manager's, the UI shall show its difficulty as a band word where it has one, and beside each choice that gives the work or an interview to an engineer, that engineer's skill and stress band words.
- [x] **UI-LINE-008**: When the recap is shown for the line manager, the UI shall show as what changed each engineer the level reports, with their band changes and that week's notes, each engineer rated at the end of the review period, each habit that fell back, each expired work item by its kind and its subject's name, each engineer whose final evaluation waits for the player, each project the player's manager assigned, the level's recalled memory as a line under "Your people", and each project that shipped, as "{project} shipped on time." or "{project} shipped {n} weeks late." ("1 week" for one), or "A quiet week." when there are none of these; and shall show as the routine part, inside the recap's disclosure, what each habit did and each goal's progress.

## Handover

- [x] **UI-HAND-001**: When the handover screen is shown, the UI shall say the player has been promoted to the next level and ask who leads their team now, offering each handover choice: an engineer with their name, skill and trust as band words and their want if a 1:1 revealed it, and the outside hire described as a capable manager the player doesn't know yet, with a line saying what each costs: "Someone from the team leaves it an engineer short, and starts out learning the job unless they trust you and want to grow. An outside hire keeps every engineer, but a stranger in charge unsettles the team at first."
- [x] **UI-HAND-002**: When the player picks a handover choice, the UI shall send the hand over command with that choice.

## Senior manager panels and scenes

- [x] **UI-SENIOR-001**: When the week screen is shown for the senior manager in the level's first month, until the player starts it, the UI shall show a scene before anything arrives with the senior manager's habits, a line on what each does, How to play, and a Start month 1 button.
- [x] **UI-SENIOR-002**: When the week screen is shown for the senior manager, the UI shall show a card per manager with name, personality, performance level, motivation and stress as band words, management skill as a skill word, their want or that it is unknown, and their memory notes, and under it their team.
- [x] **UI-SENIOR-003**: When the UI shows a senior manager's team, it shall show its name, headcount, motivation and stress as band words, attrition risk as a risk word, and its projects as the line manager's projects panel shows them, labelled "as *manager* tells it", or "as you saw it" when the view marks the bands as true; a team with no manager shall say "No manager yet".
- [x] **UI-SENIOR-004**: When the week screen is shown for the senior manager, the UI shall show the senior manager's habits panel: oversight per manager, 1:1s with managers, backfill, skip-level listening and new work for an idle team, each sending a plan command when changed, and the help line under the managers and habits panels' headings.
- [x] **UI-SENIOR-005**: When the current moment is the senior manager's calibration, the UI shall show for each team its manager's proposal beside what it delivered, as counts at each rating, with a control per rating to move a head down or up a rating, a control per team that sets its moves to those that bring its proposal to what it delivered, a control that does so for every team, the group's curve beside the top ratings the teams would hold as the moves stand and beside the top ratings they would hold set to what they delivered, naming top ratings as exceeds and outstanding, updated as heads move, an Accept every proposal button that sends `acceptAll`, and a Settle calibration button that sends `settle:` with every team's moves.
- [x] **UI-SENIOR-011**: When the senior manager's calibration is settled over the curve, the UI shall say how many top ratings the group holds against how many the curve allows, and offer to argue for an exception, saying it spends reputation and holds only with a good or excellent one, and to let the room trim.
- [x] **UI-SENIOR-006**: When a choice of a senior manager moment depends on a manager, the UI shall show that manager's management skill as a skill word beside it.
- [x] **UI-SENIOR-007**: After a senior manager choice applies, the UI shall show a chip for each band that moved in a manager's motivation, stress or management skill, a team's shown motivation or stress, the player's energy or reputation, and for each change in a team's headcount.
- [x] **UI-LINE-011**: When the recap is shown for the line manager and the level reports how its projects moved, the UI shall show each as "{project} went from {start} to {end} of {scope}: {causes}.", its causes as "{cause} cost {n}" or "{cause} added {n}" ("fixing the debt first", "rolling the change back", "approvals that slipped", "this week's situations", "a setback", "the team's work") joined in a list, costs first, under "Projects that lost ground" among what changed when the project ended the week lower than it started or had a setback, and under "Projects" in the recap's routine part otherwise.
- [x] **UI-QUIT-001**: When the recap is shown for the line manager or the senior manager and the level reports someone who quit, the UI shall show among what changed, under "Who left", "{name} quit, after {n} weeks of low motivation and {m} of high stress, trusting you little." with each clause only when it holds (or "{name} quit, for reasons of their own." when none does), followed by "The last thing between you: {note}." when there is a note; and for the senior manager, the director and the VP, for each team, group or division the level reports losing heads, "{team} lost {n} engineer(s), {k} of them one(s) you'd have kept.", the second clause only when {k} is above zero.
- [x] **UI-QUIT-002**: When the UI shows the card of an engineer, manager, senior manager or director the view marks restless, it shall show under their mood "Restless: may leave within weeks unless they get what they want."
- [x] **UI-SENIOR-008**: When the recap is shown for the senior manager, the UI shall show as what changed each manager and team the recap reports with its changes, heads that left or joined, projects that shipped, as "{project} shipped on time ({team})." or "{project} shipped {n} weeks late ({team}).", projects that slipped, each project the player's manager gave a team, under "New work", as "Your manager gave {project} to {team}.", what came of last month's approvals under "What came of it", or "A quiet month." when there are none, and inside the recap's disclosure, titled "The whole month", the habits' lines and each goal's progress.
- [x] **UI-SENIOR-009**: When a review or the ended screen is shown for the senior manager, the UI shall name the senior measures (projects shipped on time, projects on schedule, people you'd have kept who left, team motivation, team stress, how much your managers grew, teams that held up, calibration quality, your reputation, and each goal by its text), and the ended screen's stayed ending shall read "You stayed a senior manager. Three years went by without the promotion."
- [x] **UI-SENIOR-010**: When the ended screen's career summary reaches the senior manager, the UI shall add the senior manager's part: the months played at the level, and the managers who joined and who were let go.

## Saving

- [x] **UI-SAVE-001**: When the page starts with a saved run in storage, the UI shall restore it and show it.
- [x] **UI-SAVE-002**: When a run begins and after every command that applies, the UI shall write the run's save to storage.
- [x] **UI-SAVE-003**: When a restored run was rebuilt, the UI shall show a notice saying how many of its commands still applied, until the player's next command.
- [x] **UI-SAVE-004**: If a saved run in storage fails to load, then the UI shall show the start screen with a message and leave the stored save in place until a new run begins.
- [x] **UI-SAVE-005**: If storage cannot be read or written, then the UI shall keep playing without saving, show a notice once, and remove the stored save if it can.
- [x] **UI-SAVE-006**: When the player exports from a run screen, the UI shall download the save as a JSON file named `manager-simulator-<seed>-week-<week>.json`, `<week>` being the week the screen shows (the header's week on the week screen, the week a recap, review or ended screen is about), through an object URL it revokes after the download starts.
- [x] **UI-SAVE-007**: When the player imports a save file from the start screen, or from a run screen and confirms replacing the current run, the UI shall restore it, and if it loads, replace the current run with it, save it and show it; if it fails, show a message and leave the current run as it was.
- [x] **UI-SAVE-008**: When the player discards from a run screen and confirms, the UI shall remove the stored save and show the start screen with a new seed; if they cancel, the run and its save stay as they were.

## Band words

- [x] **UI-BAND-001**: The UI shall name bands 0 to 4 as: motivation struggling, flat, fine, good, energized; stress calm, steady, busy, strained, overwhelmed; energy running on fumes, tired, okay, good, fresh; skill and work difficulty learning, developing, capable, strong, expert; risk and tech debt low, moderate, elevated, high, severe; reputation poor, mixed, fair, good, excellent; trust wary, guarded, neutral, trusting, loyal.

## Review and end

- [x] **UI-REVIEW-001**: When the review screen is shown, the UI shall show the outcome in plain words (continuing, promoted, staying at the active level, or managed out), the rating, the ceiling's reason when the review returned one, the score in secondary text with its range, each measure with its name, its value in words, its verdict in words and, in secondary text, its number, target and tolerance, each of the quarter's debriefs with the situation's title (or its id when the loaded content has no such situation) and what happened in words ("You dealt with it" with its debrief text when resolved, "You let it wait" with the situation's wait debrief when ignored and it has one, "It passed before you got to it" when expired), and an Acknowledge button that sends the acknowledge command.
- [x] **UI-REVIEW-002**: When the review screen is shown, the UI shall show the standing in words: for a margin up, "One measure a step better would have made it {next rating}."; for a margin down, "One measure a step worse would have made it {next rating down}."; toward promotion, "One more review rated exceeds or better and you'll be promoted." for one more, followed by "It's your last review at this level." when one review is left, "Promotion takes two reviews in a row rated exceeds or better, and {n} are left at this level." for two in a row, with the reviews left in words, "Promotion opens in {n} reviews, then takes two in a row rated exceeds or better." for not open yet, "There aren't enough reviews left at this level for a promotion." for out of time, and nothing for promoted or ended; for what held it back, "What kept this from exceeds: {measures}.", naming the measures as the review's table does, joined with commas and a final "and", or "Every measure was on target or better; exceeds takes more of them above target." when none was below; and for a plan, "One more review rated partial or below puts you on an improvement plan." on a coaching plan and "One more review rated partial or below and you'll be managed out." on an improvement plan.
- [x] **UI-LINE-009**: When the review screen is shown for the line manager, the UI shall name its measures projects shipped on time, projects on schedule, people who quit, team motivation, team stress, 1:1s held and your reputation, a goal by its text, and give their values in words: counts as numbers or none, shares as all, none or a percentage, motivation, stress and reputation as band words, and a goal as met or missed.
- [x] **UI-END-001**: When the ended screen is shown, the UI shall say why the run ended (burnout, managed out, stayed at the level it ended at, or completed), show the final week's recap with its disclosure open, and offer a button that returns to the start screen with a new seed.
- [x] **UI-END-002**: When the ended screen is shown, the UI shall show a career summary before the final week's recap: the weeks played, counting from 1, and the player's review ratings in order, followed by the part of the summary of each level the run reached, in order.
- [x] **UI-LINE-010**: When the ended screen is shown for the line manager, the UI shall add to the career summary the projects shipped on time, the engineers who joined, and the engineers who left with why (quit, let go, moved).

## Content and build

- [x] **UI-CONTENT-001**: When the page starts, the UI shall load the compiled situation bundle through the situation engine, listing invalid situations' errors on the page in the development build and dropping them silently in the production build.
- [x] **UI-BUILD-002**: When the game is built for production, the build shall put a Content-Security-Policy `<meta>` tag first in the page's head with the policy the UI design sets, which allows no inline script, no `eval` and no network connections.
- [x] **UI-BUILD-003**: When the game is built, the build shall emit every image the page uses as its own file, and inline none into the page, its stylesheets or its scripts as a `data:` URL, which the Content-Security-Policy's `img-src 'self'` would block.
- [x] **UI-BUILD-004**: When the game is built with git and the whole commit history available, the build shall stamp the version `v<major>.<minor>.<count> (<commit>)`, where `<major>` and `<minor>` are the first two numbers of `package.json`'s `version`, `<count>` is the number of commits reachable from the commit being built that are not reachable from the parent of the most recent commit that set `package.json`'s version to that major and minor (so the commit that set it counts as 1, and a major or minor not yet committed counts 0), or every commit reachable when no commit ever set one, and `<commit>` is that commit's short hash.
- [x] **UI-BUILD-005**: If git is unavailable or the history is shallow when the game is built, then the build shall stamp the version `unversioned`.
- [x] **UI-BUILD-006**: While the game is served by the development server, the UI shall use the version `development`.
- [x] **UI-BUILD-007**: Every relative import in the files Vite's configuration loads, directly or through other imports, shall name the imported file with its extension, or a directory's `index.ts`.
- [x] **UI-BUILD-001**: When the game is built, the build shall compile the situations in `content/situations/` into the bundle, fail on an invalid situation, and emit static files with no inline script.

## Hosting

- [x] **UI-HOST-001**: The site's CloudFormation template shall serve the game from a private S3 bucket, blocking all public access and readable only by the site's CloudFront distribution, over HTTPS only, under `www.manager-simulator.io` and `manager-simulator.io`, with a certificate for both.
- [x] **UI-HOST-002**: The site's distribution shall send on every response the UI design's Content-Security-Policy with `frame-ancestors 'none'` added, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Strict-Transport-Security` of at least a year, and `Referrer-Policy: no-referrer`.
- [x] **UI-HOST-003**: When a request reaches the site under the bare domain, the site shall answer with a permanent redirect to the same path and query on `www.manager-simulator.io`.
- [x] **UI-HOST-004**: The site's template shall give the deploy a role trusted only for the repository's `main` branch through GitHub's OpenID Connect provider, allowed only to list and write the site's bucket and invalidate its distribution.
- [x] **UI-HOST-005**: The site's template shall publish DNS records saying the domain sends no mail (a null MX, SPF that allows no sender, and DMARC that rejects), and a CAA record allowing only Amazon to issue its certificates.
- [x] **UI-HOST-006**: When a push to `main` passes its checks, the deploy shall build the game for the domain's root, upload it to the site's bucket with the page uncached as `text/html; charset=utf-8`, the hashed assets under `assets/` cached for a year, and every other file cached for an hour, removing files no longer built, and invalidate the page and those other files.
- [x] **UI-HOST-007**: When a push to `main` passes its checks, the deploy shall publish to GitHub Pages only a page, as both its index and its not-found page, that holds no script, sends the browser to `https://www.manager-simulator.io/` at once and links there for a browser that does not follow it.
- [x] **UI-HOST-008**: When the site's stack is given a Google Search Console verification value, its template shall publish it as a TXT record on the bare domain beside the SPF record, and publish only the SPF record when none is given.

## Sharing and search

- [x] **UI-SHARE-001**: The page's head shall hold a description, a canonical link to `https://www.manager-simulator.io/`, and Open Graph tags for its title, description, type `website`, URL and preview image, the image with its absolute URL, width 1200, height 630 and alt text.
- [x] **UI-SHARE-002**: The page's head shall hold a large-image Twitter card with the title, description and preview image, and a theme colour.
- [x] **UI-SHARE-003**: The built site shall hold the preview image as a 1200×630 PNG, and the icon as an SVG favicon, a 32×32 PNG favicon, a 180×180 touch icon and 192 and 512 pixel PNGs named by a web app manifest, each linked from the page's head.
- [x] **UI-SHARE-004**: The built site shall hold a `robots.txt` that allows every crawler and names the sitemap, and a sitemap that lists `https://www.manager-simulator.io/`.
- [x] **UI-SHARE-005**: The page's head shall load nothing from another origin and hold no inline script, so it stays within the Content-Security-Policy.

## The director's screens
